# APCOSYS — сборка продукта и передача к интеграции

Дата: **23 октября 2026 года**. Рабочий репозиторий: [IMONsergey/Assaasdev](https://github.com/IMONsergey/Assaasdev).

## Результат

В новом репозитории собран работающий клиент существующего SaaS: интерфейс, состояние приложения, транспорт website API, управляемые сценарии, отдельный интерактивный деморежим, тесты и контейнерная конфигурация. На момент начала разработки репозиторий был пустым.

Готовность клиентской сборки отделена от готовности клиентского окружения. Деморежим позволяет провести предметную приёмку интерфейса и сценариев. Для запуска с настоящими данными необходимо подключить существующий backend и выполнить перечисленные ниже проверки с реальными тестовыми ролями и сервисами. Новый backend, поисковый индекс, платёжный процессор или инфраструктура сканирования этим репозиторием не заменяются.

### Исправленные принципиальные расхождения

1. **Отсутствовавший клиент приложения.** Дизайн и review-модели превращены в маршруты, компоненты, валидацию, запросы и управляемое состояние.
2. **Конфликт старого scope и нового API.** Реализованы сохранённые запросы, ротация ключа, подтверждение email, cancel/resume и ограниченные ссылки, которые подтверждены новым контрактом.
3. **Неверные обещания данных.** Длина страницы не объявляется общим количеством хостов; неизвестное, пустое и нулевое различаются; счётчики хостов и наблюдений сервисов не смешиваются.
4. **Потеря контекста.** Сохраняются применённые условия, private task scope, выбранный сервис и исходное тело выгрузки. Для saved query без discriminator набор данных выбирается явно.
5. **Тарифицируемые повторы.** Автоматические retries/refetch отключены. Обрыв изменения или потеря ответа дают отдельное состояние неопределённого исхода с проверкой актуального состояния.
6. **Ошибки идентификации.** HTTP 202 означает Pending2FA, а не успешный вход; logout завершает все сессии, отдельная операция завершения других сессий сохраняет текущую.
7. **Подмена текущего аккаунта общей ссылкой.** Метаданные запроса с share token не обновляют баланс пользователя, открывшего ссылку. Происхождение ответа устанавливает клиент по исходному запросу.
8. **Большие данные и мобильный экран.** 1 000 сервисов имеют локальную пагинацию и фильтр; интерфейс перестраивается на 390/320 px. Исходные шрифты, логотип и иллюстрации доступны локально.
9. **Платежи.** Checkout, возврат из провайдера, received transfer и предоставленная подписка разделены. Большие криптосуммы и номера блоков сохраняются строками без потери точности.
10. **Выгрузка.** Несовместимый Full+CSV исключён, поток не разбирается как JSON-объект, память ограничена. Отказ записи на диск не считается завершённым скачиванием.

## Почему выбран этот стек

React 19, TypeScript и Vite продолжают техническую основу клиента. Для авторизованного рабочего интерфейса, уже имеющего cookie HTTP/WebSocket backend, это позволяет реализовать приложение без переноса аккаунтов, новой базы подписок и привязки к дополнительному облаку. React Router обслуживает маршруты; TanStack Query используется с отключёнными автоматическими повторами; сложный протокол website API вынесен в самостоятельный transport.

Дизайн строится на семантических CSS-токенах и реальных Figma-материалах. Доступны Light/Dark/System, две плотности, три размера текста и reduced motion. Базовый язык UI — английский согласно макетам. Русский язык не представлен как готовая локализация.

Клиент собирается в статические файлы; Nginx обслуживает приложение и проксирует существующий API на одном HTTPS origin. Это сохраняет независимость от хостинга. Детали и проверяемые ограничения: [DEPLOYMENT.md](DEPLOYMENT.md).

## Что принимать в этой версии

Полное сопоставление 52 методов и HTTP-маршрутов находится в [IMPLEMENTATION-COVERAGE.md](IMPLEMENTATION-COVERAGE.md). Основные сквозные маршруты:

- Поиск → применённые условия → результаты/фасеты → объект → сервис/HTTP/TLS/CVE → возврат.
- Сохранение → список → выбор Public/Private → открытие → подтверждённое удаление.
- Ограниченная ссылка → неизменяемый запрос → явная загрузка аналитики без скрытого расхода открытий.
- Files/Buckets → фильтры → группировка → объект → потоковая выгрузка.
- Scanner → ввод/CSV → проверка стоимости и портов → задача → расписание → отдельное удаление задачи, плана или результатов.
- Login/Signup/Recovery → Pending2FA/verification → аккаунт; профиль, безопасность, сессии, команда и ключ.
- Тариф → период/продукт/промокод/способ → checkout/invoice → проверка платежа → актуальная подписка; отдельно tracked addresses и точные транзакции.
- Уведомления и индивидуальные параметры вида, включая мобильную навигацию и клавиатуру.

Не добавлены операции, которых нет в действующем контракте: новые роли/workspaces, email-приглашения, несколько API-ключей/scopes, произвольный мониторинг, pause сканирования, постоянная очередь экспортов и несуществующий resend endpoint. Серверно игнорируемые bucket-фильтры и scanner workers не выдаются за работающие параметры.

## Остаток до реальной сдачи

Ниже конкретные входные данные и результаты, которые нельзя заменить макетами или демо:

| Область | Нужный вход | Критерий завершения |
| --- | --- | --- |
| Окружение | Фактический staging API origin, версия backend, публичный HTTPS-домен приложения | SPA deep links, `/backend`, WebSocket, callback и short-link работают на одном согласованном origin. |
| Пользователи | Тестовые Guest/Free/Plus/Expert/Business, Owner/Member, Pending2FA | Cookie переживает reload; expiry/logout/revocation и ограничения каждого плана соответствуют ответам сервера. |
| Email и внешние входы | Рабочая почта, Google callback, реальные Telegram bot/widget параметры | Signup/recovery/email change доставляют коды; callback и Pending2FA доходят до нужного состояния. Telegram включается только с настоящей конфигурацией. |
| Протокол | Серверные ответы search/facets и private host detail | Порядок/корреляция partial frames, отсутствие ID у private replies, quotas и shared opens проверены на реальном сервере. |
| Оплата | Sandbox провайдера, тестовые цены/счета и callback | Подтверждённый платёж обновляет entitlement; pending/failed/interrupted не создают ложную подписку. |
| Сканер | Разрешённые тестовые цели, cron timezone и семантика CIDR/дедупликации | Реальная задача создаётся один раз, выполняется, показывает результаты; изменение/удаление и неизвестный исход проверены. |
| Экспорт | Business-аккаунт и достаточно большой тестовый набор | NDJSON/CSV/caps/headers/Range подтверждены; прерванный файл продолжается с правильной границы и тем же телом. |
| Развёртывание | Выбранный host/registry и HTTPS proxy | Контейнерный smoke и staging browser acceptance зелёные; записан image digest и доступен rollback. |

Для показа продукта можно использовать готовый деморежим и приложенную галерею. Для объявления рабочего production релиза нужны результаты этой таблицы. Исторические 548 Figma-состояний и 3 868 исследовательских спецификаций не объявляются пройденными runtime-тестами.
