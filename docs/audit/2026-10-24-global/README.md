### Как трактуется стоимость аналитики

Для public WebSocket analytics используется контракт `ceil(loaded categories / 4)`. Когда сохранённые настройки известны, UI показывает **Estimated**, например 2 search credits для пяти включённых категорий. Фактические серверные metadata остаются авторитетными. При неизвестном или нулевом наборе нет обещания нулевой стоимости: выводится формула. Guest получает подпись о daily request, private — собственную оценку, shared — link use и доступ владельца.

Вес HTTP REST API analytics в rate allowance не является стоимостью этой кнопки. Публичный пример полного search-with-analytics также не подменяет оценку отдельного действия. Источник существующего WS-контракта: [API-INTEGRATION](../../API-INTEGRATION.md), `src/api/catalog.ts` и [переданный ранее web-api.md](https://github.com/IMONsergey/apcosaas/blob/2970396891c2dad38fa0459e668aabee3ed6cd21/docs/api/2026-10-22/web-api.md).

## Дополнительно найденные и исправленные проблемы

| Область | Причина | Изменение |
| --- | --- | --- |
| Search history около 768 px | Desktop sidebar оставляет узкую рабочую область, но viewport breakpoint ещё не перестраивает toolbar | Перестройка по фактической ширине `workspace` |
| Платёжные сценарии около 768 px | Та же зависимость от окна вместо доступного контейнера | Существующие карточки переключаются в одну колонку по ширине workspace |
| Crypto activity в узком диалоге | Portal находится вне billing container, его responsive query не применяется | Собственный container для содержимого транзакций, одна колонка на узкой ширине |
| Длинные labels, версии, vendors, заголовки наборов | Неразрывные значения шире карточки | Локальное ограничение ширины и перенос; обычные данные сохраняют композицию |
| Очень длинное Unicode-имя файла | Даже короткий по числу символов суффикс CJK/emoji может быть широким | Суффикс ограничен долей доступной ширины, виден конец с расширением; полное значение остаётся в деталях и копировании |
| Host Data без field_headers | Счётчик смотрел только на заголовки | Количество полей следует реальным строкам; исправлены формы 1 row / 1 field |
| Очистка поиска API docs | Кнопка исчезает после Clear, фокус уходил в body | Фокус возвращается в поле поиска |
| API docs на мобильном | Переход к статье мог попасть под плавающую кнопку меню | Scroll offset учитывает мобильную навигацию; широкий table region доступен с клавиатуры |
| Повторный импорт CSV после ошибки | Native file input сохранял прежний выбор | Поле сбрасывается после получения File; тот же файл можно выбрать снова. Позднее чтение после закрытия игнорируется |
| Scanner pagination на мобильном | Scroll-to-table не учитывал плавающее меню | Увеличен локальный scroll margin |
| Кнопки навигации Search | На текущем CI-снимке New search унаследовал подчёркивание обычной ссылки при hover | Кнопкообразные search-secondary-link сохраняют общий hover без подчёркивания |
| Account | Длинные значения; при несовпадении паролей фокус не переходил к подтверждению | Перенос в локальных местах; ошибка фокусирует Confirm new password |

## Рекомендации из анкеты, которые требуют отдельного решения

1. **Единый тарифный источник.** Держать marketing, demo и backend pricing согласованными. UI уже подчиняется серверу. До коммерческого запуска подтвердить entitlement Business и фактическое списание на настоящем backend.
2. **Показать ценность на одном расследовании.** В существующем маркетинговом demo/story провести пользователя по query → filter → host → service. Пример анкеты: example.com → Germany → host → ssh. Числа найденных записей обозначать демонстрационными.
3. **Сценарии под роли.** В имеющихся use-case блоках показать задачу, действие и получаемый результат для каждой аудитории. Для этого не требуется перестраивать SaaS-навигацию или добавлять обязательный onboarding.
4. **Пояснить ценность Plus.** После подтверждения тарифной модели дать один честный пример рабочего объёма в существующих plan details/help. Не приравнивать credits к гарантированным находкам или завершённым расследованиям.
5. **Проверить с новыми пользователями.** Первый запрос, фильтр, переход к service и выбор тарифа должны быть проверены без подсказок автора. Фиксировать время, ошибки и понимание расхода. Экспертная анкета не заменяет такой проверки.

Маркетинговый APCOCLEAR2 — отдельный проект: эти рекомендации не отмечаются как внесённые изменения его страниц.
