# APCOSYS: проверка качества основных сценариев

Дата: 24 октября 2026. Проект: Assaasdev. Исходная опубликованная версия: `8f23c166884b7b34da6eb8f2fcdb185f06d1dfa7`.

Это дополнительный проход после [глобального аудита desktop и адаптива](../2026-10-24-global/README.md). Цель — убрать подтверждённые сбои в последовательностях действий и крайних состояниях, сохранив утверждённую композицию, палитру, типографику, общие компоненты и интерфейс без шапки. Публичная сборка использует демонстрационный адаптер.

## Что доведено

| Область | Подтверждённая проблема | Решение и критерий приёмки |
| --- | --- | --- |
| Files / Buckets | Возврат на Files после загрузки Buckets показывал стартовый экран вместо уже полученной выдачи | Возвращается завершённая выдача с теми же фильтрами. Переключение не отправляет повторный запрос и не отменяет ожидающий ответ другой вкладки |
| Остановка поиска | После Stop waiting пустое состояние другой вкладки могло исчезать | Остановка относится только к запросу своей вкладки; соседняя сохраняет доступные действия |
| Метаданные файлов | Неверные типы `key`, `extension`, `alphabets` могли приводить к ошибке отображения | Проверка ответа до строковых и списковых операций. Штатная ошибка сохраняет фильтры и предупреждает о возможном расходе; автоматического повторения нет |
| Экспорт бакетов | Download records из Buckets выбирал Files | Начальный Record detail соответствует текущей вкладке: Bucket hosts или Files; существующие значения API сохранены |
| Подготовка фильтров до входа | Переход к входу терял keywords и дополнительные фильтры | Валидный черновик и текущая вкладка проходят через returnTo; после входа поиск требует отдельного действия |
| Saved queries | Переход из Save терял исходный запрос, Analytics и приватный контекст | Back to results возвращает запрос, вид аналитики, task IDs и путь обратно к Scanner |
| Поддержка | Ошибка имени отображалась под полем сообщения | Каждая ошибка связана со своим полем; фокус у первого ошибочного поля, правка одного поля очищает только его ошибку |
| Длинное обращение | Прокручиваемый предпросмотр не имел доступного имени и общей рамки фокуса | Именованная область Message preview, клавиатурная прокрутка и видимый фокус; footer доступен на 320 px |
| Copy | Обработчик мог перехватить запрет clipboard, а CodeCanvas всё равно показывал Copied | Подтверждение зависит от фактического результата. Отказ не показывает успех, следующая попытка может восстановиться |
| Авторизация | Вход и гостевой режим могли выполняться одновременно | Общая блокировка конкурирующих действий с восстановлением после ошибки и сохранением returnTo |
| Профиль | Запрос изменения и подтверждение кода могли пересекаться | Взаимные ограничения до завершения запроса; при неизвестном результате остаётся проверка текущего состояния |
| Пароль | Ошибка несовпадения оставалась после редактирования | Сообщение очищается при правке нового пароля или подтверждения |
| Settings на планшете | Два боковых меню оставляли узкую колонку, но строки сохраняли desktop-компоновку | Перестройка по фактической ширине settings-content; custom select, темы, профиль и выход проверяются на 768/320 px с текстом 125% |
| Payment ID | После изменения ID мог оставаться результат предыдущего платежа | Редактирование очищает старый итог; поле заблокировано во время проверки и неопределённого результата; старый ID из URL не возвращается сам |
| Промокод | Неполный ответ read-only проверки мог навсегда блокировать повтор того же кода | Чтение допускает явный повтор; ограничения неизвестного результата покупки не изменены |
| API access | План мог переопределять явно выключенный api_access | Серверный boolean имеет приоритет; старый формат показывает Included in plan, неизвестный доступ — Not confirmed с проверкой аккаунта |
| API docs | Поиск вложенного поля ответа открывал вкладку Request | Открываются Response, нужная группа и найденная строка. Ссылка сохраняет только известные публичные имена схемы, без исходной строки поиска |
| Навигация API docs | Inline-переход к ключу/лимитам мог терять клавиатурный фокус | Фокус переходит на актуальную вкладку; Back восстанавливает доступную точку чтения |
| Private Scanner | Ошибка чтения списков могла выглядеть как требование сменить тариф | Ошибка соединения отделена от подтверждённого ограничения доступа; у каждой есть подходящее действие восстановления |
| Task details | Открытые детали оставались снимком на момент открытия | Детали следуют последнему полученному состоянию задачи; Refresh task, переход к результатам и честное сообщение при исчезновении из списка |
| Подтверждение создания задачи | Пустой schedule мог совпасть с периодической задачей; несколько новых совпадений были неоднозначны | Однократный и периодический запуск различаются; потерянный ответ сопоставляется только с одной новой задачей при известном исходном списке |

## Проверки и статус

На этапе подготовки изменений `npm run check` завершён успешно: TypeScript, **215 unit-тестов в 31 файле**, production-сборка. `npm run build:demo` и `git diff --check` также успешны.

Независимая повторная проверка обнаружила связанный риск Payment ID: переход View payments к тому же завершённому invoice мог сбрасывать его статус и блокировать следующую покупку. Исправлены same-ID переход, отложенное применение другого ID во время проверки и освобождение только завершённого invoice при смене reference. Сценарий wallet дополняет проверка отсутствия второго списания.

Итоговые результаты общего CI, новой публикации и просмотренные снимки будут добавлены после завершения проверки. Наличие новых E2E пока не считается свидетельством их прохождения.

Новые сценарии проверяют восстановление контекста, отсутствие незапрошенных повторов, конкурирующие действия, отказы clipboard, неполные ответы, правильные error states, геометрию и клавиатуру. Они дополняют существующий глобальный набор для light/dark, desktop, мобильных ширин, модальных окон, длинных данных и reduced motion.

## Границы вывода «5 из 5»

Пять баллов не присваиваются автоматически по числу исправлений или тестов. Этот проход подтверждает конкретные критерии интерфейса на проверенной сборке. Из исходной анкеты остаётся отдельная проверка с новыми пользователями: первый поиск → фильтр → host/service → сохранение/возврат, понимание тарифа и расхода без подсказок автора.

Публичное demo не подтверждает live email/2FA, фактические платежи, доступы настоящего backend, актуальность индекса и нагрузочную производительность. Кэш Files/Buckets живёт в памяти открытой страницы: полная перезагрузка восстанавливает параметры, а новый поиск запускается явно. Полный WCAG-аудит и кроссбраузерная сертификация этим отчётом не заявляются.
