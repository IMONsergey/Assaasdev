# APCOSYS: проверка качества основных сценариев

Дата: 24 октября 2026. Проект: Assaasdev. Исходная опубликованная версия: `8f23c166884b7b34da6eb8f2fcdb185f06d1dfa7`.

Это дополнительный проход после [глобального аудита desktop и адаптива](../2026-10-24-global/README.md). Цель — убрать подтверждённые сбои в последовательностях действий и крайних состояниях, сохранив утверждённую композицию, палитру, типографику, общие компоненты и интерфейс без шапки. Публичная сборка использует демонстрационный адаптер.

## Что доведено

| Область | Подтверждённая проблема | Решение и критерий приёмки |

## Проверки и статус

На этапе подготовки изменений `npm run check` завершён успешно: TypeScript, **215 unit-тестов в 31 файле**, production-сборка. `npm run build:demo` и `git diff --check` также успешны.

Независимая повторная проверка обнаружила связанный риск Payment ID: переход View payments к тому же завершённому invoice мог сбрасывать его статус и блокировать следующую покупку. Исправлены same-ID переход, отложенное применение другого ID во время проверки и освобождение только завершённого invoice при смене reference. Сценарий wallet дополняет проверка отсутствия второго списания.

Первый общий [CI-прогон](https://github.com/IMONsergey/Assaasdev/actions/runs/40113560543) на `849996c80472e7f0be1253ac88934fc6d7321a5b`: TypeScript, 215 unit-тестов, production-сборка и container/proxy успешны; **267 из 269 E2E прошли, два завершились ошибкой**. Это не успешный релизный прогон. Trace подтвердил гонку быстрого Back в документации: URL уже менялся, промежуточный Request ещё не был отрисован, а фокус оставался на нём. Исправление сохраняет строгую проверку фокуса без ожидания промежуточного render. Второй сбой был неоднозначным локатором Current password в сохранённых панелях Profile/Security; локатор ограничен видимой панелью Security, проверки не убраны.

По свежим снимкам CI отдельно обнаружена излишне узкая колонка Settings при 768 px и тексте 125%. Отсутствия горизонтального overflow оказалось недостаточно: проверка дополнена оценкой самой композиции. Итоговые результаты повторного общего CI, новой публикации и просмотренные снимки будут добавлены после завершения проверки.

Новые сценарии проверяют восстановление контекста, отсутствие незапрошенных повторов, конкурирующие действия, отказы clipboard, неполные ответы, правильные error states, геометрию и клавиатуру. Они дополняют существующий глобальный набор для light/dark, desktop, мобильных ширин, модальных окон, длинных данных и reduced motion.

Дополнительный review срока хранения выявил, что неактивная запись Files могла удалиться через 60 секунд, хотя её содержимое отображалось при текущем запросе Buckets. Это воспроизведено вручную в том же preview: Files → запрос Buckets → Files → чтение дольше минуты → Filters → Cancel; [выдача исчезла при сохранённых фильтрах и балансе](review/01-files-expired-in-preview.jpg). Поэтому таймер удаления заменён сохранением ограниченного числа снимков. Регрессия включает 61 секунду виртуального времени, обычный повторный render через Filters → Cancel и проверку ровно одного запроса каждого типа.

## Границы вывода «5 из 5»

Пять баллов не присваиваются автоматически по числу исправлений или тестов. Этот проход подтверждает конкретные критерии интерфейса на проверенной сборке. Из исходной анкеты остаётся отдельная проверка с новыми пользователями: первый поиск → фильтр → host/service → сохранение/возврат, понимание тарифа и расхода без подсказок автора.

Публичное demo не подтверждает live email/2FA, фактические платежи, доступы настоящего backend, актуальность индекса и нагрузочную производительность. Files/Buckets использует ограниченный кэш в памяти — до пяти неактивных записей плюс текущий запрос. Он очищается при смене аккаунта/выходе и не является постоянным хранением: полная перезагрузка восстанавливает параметры, а новый поиск запускается явно. Полный WCAG-аудит и кроссбраузерная сертификация этим отчётом не заявляются.
